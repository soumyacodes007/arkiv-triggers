# OpenTrigger: proof

Everything OpenTrigger claims, with the on-chain evidence to check it. Rules, claims, receipts and
heartbeats are entities on Arkiv's Tiramisu testnet (chain 7738577), and each one's `$creator` is set
by Arkiv to the wallet that wrote it, so a receipt shows which worker fired a rule and cannot be
forged. Links open the [Tiramisu explorer](https://tiramisu.explorer.arkiv.network).

**Check it yourself:** `npm ci && npm run evidence` rebuilds the on-chain section below from Arkiv,
with public queries only (no key needed).

## The claims, and where to check each

| Claim | Evidence |
|---|---|
| Rules fire on time, and a receipt records each firing | Receipts below: deadline block vs the block it fired at, mostly 0–1 blocks |
| Every action works: Telegram, signed webhook, extend, receipt | One receipt of each kind below, with its rule and its transaction |
| A rule whose target was deleted (not expired) is not fired | A `skipped` receipt below: "the target was deleted before it expired" |
| A public worker refuses webhooks to private addresses | The `failed` webhook receipts: test rules pointing at `127.0.0.1` |
| Rules fire exactly once across several workers | Test runs below: 100 rules on two workers, 0 duplicates |
| Nothing secret is on Arkiv | Telegram chat IDs are stored sealed (`sealed:v1:…`) in rule payloads; keys and tokens live only in each worker's environment ([schema](arkiv/schema.md)) |

## Test runs on Tiramisu (18 October 2026)

Each suite writes real entities from the wallets above and checks them on Arkiv. Commands are run
from a clone of this repository with funded test wallets in `.env.local` (see the README).

| Suite | Command | What it does | Result |
|---|---|---|---|
| Unit tests | `npm test` | Schema round-trips, sealing, webhook signatures, the RPC client's 429 handling (no network) | 27/27 |
| One worker | `npm run test:live:worker` | Expire → receipt; a time → signed webhook to a local server; a deleted target → `skipped`; auto-extend of a `permissionlessExtension` target | 13/13; fired 0–2 blocks after each deadline |
| Two workers | `npm run test:live:network` | A crashed worker's live claim on a rule; a worker down while its rules come due; a 20-rule race | 21/21; no worker fires while another holds the lease; downtime caught up; **0 duplicates** |
| Two workers, load | `NET_RULES=100 npm run test:live:network` | 100 rules coming due over 25 blocks | **100/100 fired, 0 duplicates, all within 3 blocks of their deadline (median 1)** |
| Telegram | `npm run test:live:telegram` | A Telegram rule whose chat is sealed to one worker | 6/6; the chat is stored only sealed; one real message sent; its message ID is in the receipt; 1 block after the deadline |
| SDK | `npm run test:live:sdk` | Create, batch-create, list, audit trail, delete; `watch()` over WebSocket | 7/7 |

What changed because of these runs is in [`arkiv/friction.md`](arkiv/friction.md) and the
[README](README.md): for example, batching every write a worker has into one transaction took the
100-rule run from a median 19 blocks late to 1.

## The queries behind every number

Paste any of these into an Arkiv query tool (this is the form the SDK sends):

```
type = str('trg.receipt') AND $creator = addr(0xf856952A77F9439a55Ad418f5BB3928f4CE807Db)
type = str('trg.receipt') AND $creator = addr(0x1c92087EC55B3B4114c7647ECADe3ab0b494C9b6)
type = str('trg.receipt') AND rule = str('<rule key>')
type = str('trg.rule') AND $creator = addr(<your wallet>)
type = str('trg.worker')
```

Receipts live 30 days and rules until a week after their deadline, so these entities stay queryable
through judging. Claims (60 s) and heartbeats (5 min) are short-lived by design; the transactions that
created them remain on the explorer.
